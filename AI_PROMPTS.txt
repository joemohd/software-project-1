PROMPT: How does this backend manage file uploads?

------------------------------------------------

RESPONSE: The backend uses NestJS’s Multer integration for a single image-upload endpoint:

- **Endpoint:** `POST /api/upload/image`, with a `multipart/form-data` field named `file` (`upload.controller.ts`).
- **Validation:** Only JPEG and PNG MIME types are accepted, and each file is limited to 5 MB (`image-upload.options.ts`).
- **Storage:** Files are written to `./uploads` with a random UUID filename and the original extension. The directory is ignored by Git (`image-upload.options.ts`, `.gitignore`).
- **Serving and response:** The app exposes that directory under `/uploads`; after a successful upload, the endpoint returns `{ "url": "…" }`, built from `BASE_URL` (default `http://localhost:3000`) (`main.ts`, `upload.controller.ts`).

The upload module is registered in the app. The current endpoint is generic: it doesn’t associate files with a specific post, activity, hotel, or airline, and the documented per-entity image-count limits aren’t enforced here.

PROMPT: How easy would it be to switch from this to Cloudinary?

------------------------------------------------

RESPONSE: It should be a **small, localized backend change**. Upload handling is already behind one controller and one Multer configuration, so the main change would be replacing local disk storage in `image-upload.options.ts` with a Cloudinary upload, then returning Cloudinary’s `secure_url` from `upload.controller.ts`.

The endpoint can likely keep accepting the same `multipart/form-data` request, so the frontend should need little or no change if it already uses the returned URL. You’d also add Cloudinary credentials to environment configuration and remove or stop using the local `/uploads` static serving.

The main effort is operational: create/configure a Cloudinary account, set credentials securely in each environment, and decide how existing locally stored images will be migrated. Also, entity-specific authorization and image-count limits are not currently enforced, so switching storage alone wouldn’t add those safeguards.
